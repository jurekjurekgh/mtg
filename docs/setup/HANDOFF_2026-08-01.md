# Handoff sesji 2026-08-01

Dokument przekazania kontekstu między sesjami agentskimi (model: **1 sesja =
1 gałąź `arena/…` = 1 PR**, [WORKFLOW](../WORKFLOW.md#praca-z-sesją-agentską-arena)).
Powstał jako **odtworzenie** notatki zgubionej przy zamykaniu poprzedniej sesji
(commit lokalny nie zdążył trafić na remote) i jednocześnie jako **wzorzec
przyszłych handoffów** — sekcja „Wzorzec promptu startowego" na końcu.

Zasada: handoff jest krótki i faktograficzny. Stan bieżący mieszka w
[docs/PROJECT_STATE.md](../PROJECT_STATE.md), szczegóły techniczne w
[docs/ENGINE_MILESTONES.md](../ENGINE_MILESTONES.md) — tutaj tylko to, czego
nowa sesja nie odtworzy sama z repozytorium: **decyzje właściciela, kolejka
zadań i rzeczy zgubione po drodze**.

zewnętrznym i nie czeka na agenta.

## Kolejka zadań zatwierdzona przez właściciela (2026-08-01)

1. **Ilustracje prawdziwych kart na stole.** Kafel karty z realnej talii ma
   domyślnie renderować obraz z `imageUri` (jak w legacy HTML), hover powiększa
   ten sam obraz, syntetyczna twarz zostaje wyłącznie jako fallback (brak
   `imageUri` lub błąd ładowania). Uwzględnić: DFC (Batch 2 ma `imageUri`
   tyłu — po transformacji pokazujemy tył), tapnięcie (obrót kafla), lazy-load
   z `cards.scryfall.io`, wirtualne landy podstawowe (stały druk ilustracji).
2. **Batch 5 kart** — czeka na listę od właściciela.
3. **Etap B1 bota** — każda zmiana mierzona `node tools/benchmark.mjs`,
   tabela przed/po w opisie PR, progi w `test/bot-benchmark.test.js` wyłącznie
   w górę.

## Zasady nienegocjowalne (obowiązują każdą sesję)

- **Karta w 100% mechanik albo wcale.** Niepełna obsługa jest nieakceptowana;
  jeśli czegoś nie da się zrobić, ląduje jako TODO na szczycie
  `docs/PROJECT_STATE.md`.
- **Procedura ADR 0010 §2a przy każdej karcie:** Scryfall JSON → `docs/cards/`
  **przed** kodowaniem → definicja `supported` → testy legalne i nielegalne →
  talia w `decks/` → mechaniki **generyczne** w engine (ADR 0002, żadnych
  warunków po nazwie karty) → etykiety i log po polsku → probe partii botów
  (mechanika musi realnie padać w grach) → dokumentacja i benchmark.
- `npm test` i `npm run build` zielone **przed każdym commitem**.
- Determinizm bez `Math.random` (ADR 0005); FoW wyłącznie przez `PlayerView`;
  bez `localStorage`; artefakt stołu = jeden plik HTML (ADR 0011).
- Model sesji: 1 sesja = 1 gałąź = 1 PR rosnący kumulatywnie; **PR scala
  wyłącznie właściciel**.
- Opis PR aktualizuj przez `gh api PATCH /repos/{owner}/{repo}/pulls/{n}`
  — `gh pr edit` pada na Projects (classic).

### Checklista dla agenta zamykającego sesję

1. Zaktualizuj `docs/PROJECT_STATE.md` (stan, bloker, TODO na szczycie).
2. Załóż `docs/setup/HANDOFF_<data>.md` wg tego wzorca: co zrobiono, co zostało
   otwarte, decyzje właściciela, kolejka zadań, prompt startowy dla następnej sesji.
3. **Commituj i pushuj na gałąź sesji natychmiast** (`git push origin arena/…`).
4. Zaktualizuj opis PR (`gh api PATCH`) — kumulatywnie, wszystkie tematy sesji.
