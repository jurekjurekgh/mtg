## START TUTAJ — jesteś agentem nowej sesji? Zalicz tę listę, zanim napiszesz kod

Kolejność ma znaczenie. Ten checklist jest celowo mechaniczny — można go
wykonać bez żadnego kontekstu projektu.

1. **Weryfikacja stanu (2 minuty):**
   - `git log --oneline -3` — na `main` powinien być squash-merge PR #25;
   - `npm test` → oczekiwane **699/699 zielonych**;
   - `npm run build` → oczekiwane **44 moduły, ~713.7 kB**.
   Rozbieżność z tymi liczbami = repozytorium mówi prawdę, nie ten plik —
   STOP i zgłoś właścicielowi PRZED jakimikolwiek zmianami.
2. **Lektura obowiązkowa (w kolejności):** `AGENTS.md` →
   `docs/PROJECT_STATE.md` → ten plik w całości → `docs/WORKFLOW.md` →
   z `docs/decisions/`: **0002, 0003, 0005, 0010, 0011, 0013, 0014**.
   Zadanie dotyczy kart? Dodatkowo `docs/cards/HOW_TO_ADD_CARD.md`.
3. **Zasady nienegocjowalne (skrót — pełne brzmienie w AGENTS.md):**
   - engine generyczny: **zero warunków na nazwę/ID karty w core** (ADR 0002);
   - karta „supported" = 100% mechaniki + testy; wybór celu robi gracz,
     nie aplikacja;
   - praca wyłącznie na gałęzi sesji `arena/…`; push nigdy do `main`;
     merge wykonuje WYŁĄCZNIE właściciel (Squash and merge) i kończy sesję;
   - 1 sesja = 1 PR; każdy temat osobnym commitem; po KAŻDYM commicie
     `npm test` i `npm run build` muszą być zielone;
   - zmiana bota lub przestrzeni komend = pełny pomiar `tools/benchmark.mjs`;
     progi regresji (obecnie **0.78 / 0.53**) można tylko PODNOSIĆ;
   - komunikacja, UI i log gry po polsku.
4. **Wzór pracy nad kartami (ADR 0010 §2a):** NAJPIERW dane Scryfall —
   przez narzędzie `fetch_page` agenta (egress z sandboxa jest zablokowany) —
   zapisać do `docs/cards/scryfall-*.json`; dopiero potem definicje w
   `src/cards/card-data.js` i testy. Nowe karty dopisuj do **istniejących**
   talii singleton w `decks/` (Krok 5 w HOW_TO_ADD_CARD) — NIE twórz nowych
   plików batchowych.
5. **Pułapki środowiska** — pełna lista w sekcji niżej; absolutne minimum:
   commituj i pushuj OD RAZU po każdym fragmencie (w tej sesji token GH
   zmarł w połowie); po resecie sandboxa:
   `git fetch origin <gałąź>:refs/remotes/origin/<gałąź>` +
   `git reset --mixed origin/<gałąź>`; treść commita pisz plikiem przez
   python3 (heredoc psuje polskie cudzysłowy); `gh pr edit` nie działa
   (bug gh CLI — GraphQL Projects classic), opis PR aktualizuj przez
   `gh api -X PATCH repos/{owner}/{repo}/pulls/N -F body=@plik`.
6. **Potwierdzenie startu:** zanim napiszesz pierwszą linię kodu, odpisz
   właścicielowi krótko, WŁASNYMI SŁOWAMI: jakie zasady obowiązują i co
   zamierzasz zrobić. To bramka jakości, nie uprzejmość.
7. **Prompt startowy do wklejenia nowej sesji** (dla właściciela) — gotowy
   blok na końcu tego pliku („Prompt startowy dla kolejnej sesji").

  po resecie `git fetch` + `git reset --mixed origin/<gałąź-sesji>`),
  worktree przetrwa.
- 2026-08-05 wystąpiła **~40-minutowa awaria bootstrapu sandbox** (git clone
  przez proxy → 502 przy GitHub): wszystkie bash/write padały, GitHub API i
  endpoint gita były sprawne (weryfikacja przez `fetch_page`). Odgadła się
  sama; lekcja: commitować częściej.
- 2026-08-05 później: **utrata uwierzytelnienia GitHub w trakcie sesji**
  (`gh auth status`: „The github.com token in GH_TOKEN is no longer valid",
  push pada z „could not read Username"). Lokalne git add/commit działają.
  Lekcja: commitować fragmentami pushowanymi od razu; handoff musi mówić,
  co zostało nie.pushnięte.
