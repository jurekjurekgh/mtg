  Restauruj wierszem/zakresem i sprawdzaj `git diff` po każdej mutacji (L159).
- **`GH_TOKEN` wygasł w trakcie sesji** (dokładnie przed trzecim pushem) —
  `git push` pyta o login, `gh auth status` mówi „token is no longer valid".
  Commity lokalne są bezpieczne; odczyt (`git fetch`) przeszedł anonimowo.
  Leczenie: reconnect GitHub w Arenie i `git push origin arena/<gałąź>` —
  **nigdy** `--force` (ADR 0020 D) i nigdy prośba o token w czacie.
  **Leczone w tej sesji** przez reconnect właściciela w Arenie (nie przez agenta)
  — po nim `gh api` i `git push` działają, ale auth potrafi wygasnąć PONOWNIE w
  środku sesji, więc commity trzymamy w drzewie roboczym tylko do czasu pusha.
- Klon workspace jest **płytki** (`git rev-parse --is-shallow-repository` → true):
  `git diff HEAD~1 HEAD` rzuca `bad revision`. Przed porównaniem z bazą PR:
  `git fetch --depth=200 origin main`.

  `ą/Ą` to realne pułapki dopasowania — przed podmianą liczyć `s.count(old)`
  (jedna z mutacji tej sesji wyszła GREEN tylko dlatego, że wzór się NIE trafił;
  L159).
