## Awaria publikacji na GitHub Pages (run 38424779872) — diagnoza + naprawa czekająca na wgranie

Zgłoszenie właściciela: po scaleniu PR #164 publikacja na Pages pada
(„Multiple artifacts named \"github-pages\" … Artifact count is 4").
**Workflow nie zmieniał się od miesięcy, a dziesięć poprzednich runów przechodziło
za pierwszym razem — to nie regresja w repo.** Co się stało:

- **Próba 1:** upload `upload-pages-artifact` skończył się 15:50:09, `deploy-pages`
  ruszył 15:50:09 i zgłosił „No artifacts named \"github-pages\" were found for
  this workflow run" — świeżo wgrany artefakt nie był jeszcze widoczny w API.
  Klasyczny flake GitHuba (`deploy-pages` nie ponawia tego odczytu).
- **Próby 2–4 (re-runy):** każdy RE-RUN dokłada w TYM SAMYM runie kolejny
  artefakt o nazwie `github-pages`, a `deploy-pages` wymaga **dokładnie jednego**.
  Run skończył z czterema (`run_attempt: 4`) i od tej pory każdy re-run musiał
  paść — awaria stała się samopodtrzymująca, nie „kolejny flake".
- **Naprawa (gotowa we wzorcu):** `permissions: actions: write` + krok kasujący
  artefakty `github-pages` z POPRZEDNICH prób tego runu (przed uploadem) + krok
  czekający, aż świeży artefakt będzie widoczny na tej samej liście, którą czyta
  `deploy-pages` (maks. 20 × 3 s). Efekt: pierwsza próba przestaje zależeć od
  wyścigu, a re-run zawsze czyści po sobie.

### Dlaczego naprawa NIE jest jeszcze w `.github/workflows/` (blokada, nie zaniechanie)

Push sesji z poprawionym `.github/workflows/pages.yml` został **odrzucony przez
GitHuba**:

```
! [remote rejected] arena/aadcf997-mtg -> arena/aadcf997-mtg
  (refusing to allow a GitHub App to create or update workflow
   `.github/workflows/pages.yml` without `workflows` permission)
```

Token Appki Arena nie ma uprawnienia `workflows`, a `main` jest chroniona
(ADR 0007) — więc agent nie jest w stanie wprowadzić tej zmiany w żaden sposób.
Jedyna poprawna droga to **ręczne wgranie wzorca** (procedura: `docs/setup/workflows/README.md`).

### Co zrobić (właściciel) — w tej kolejności

1. **Wgraj wzorzec** (5 minut, przez stronę GitHuba): skopiuj 1:1 zawartość
   `docs/setup/workflows/pages.yml` do `.github/workflows/pages.yml` na nowej
   gałęzi (`ci/pages-fix`), otwórz PR i scal. Plik zawiera znaczniki
   `PENDING-UPLOAD (A)–(C)` — to zwykłe komentarze, wklej je razem z resztą
   (strażnik w `test/ci-workflow-tiers.test.js` pilnuje, że są spójne).
   **Ten PR scalaj PRZED PR #165** — inaczej merge #165 uruchomi jeszcze jedną
   publikację starym workflowem i dołoży piąty artefakt.
2. **Uruchom świeżo** (Actions → „Publikacja na GitHub Pages" → Run workflow).
   Nowy workflow sam skasuje cztery zaległe artefakty i opublikuje stronę.
   **Nie klikaj „Re-run" na starym runie** — to kolejny artefakt i kolejna awaria.
3. **Scal PR #165** (dokumentacja + strażnik; bez workflowów) — zwykłą drogą.
   Jego push do `main` uruchomi publikację, która też sama się posprząta.
4. (Opcjonalnie, na przyszłość) Nadaj Appce Arena uprawnienie `workflows` —
   wtedy takie naprawy wracają do zwykłej ścieżki PR i nie wymagają ręcznego
   kopiowania plików.
5. (Opcjonalnie) Cztery zaległe artefakty runu 38424779872
   (`11827359673`, `11827919587`, `11828709835`, `11844826622`) skasują się same
   przy pierwszym udanym uruchomieniu nowego workflowu — ręczne kasowanie nie
   jest konieczne.

### Co jest już zweryfikowane lokalnie

- Strażnik `test/ci-workflow-tiers.test.js` (4 testy): obecność i **kolejność**
  kroków (sprzątanie < upload < czekanie < deploy), realny `DELETE` na API,
  regiony `PENDING-UPLOAD` kompletne i domknięte, żywy workflow bez połowicznej
  protezy, wzorzec ↔ żywy workflow zgodne poza regionami.
- Mutacje (wszystkie czerwienieją): brak `actions: write` w wzorcu; żywy
  workflow z krokami sprzątania bez uprawnienia; odwrócona kolejność kroków.
  RED dla samej protezy: po cofnięciu regionów (git stash) 3/4 → z protezą 4/4.
- Składnia: YAML parsuje się (9 kroków w jobie `deploy`), oba skrypty `run:`
  przeszły `bash -n`, kwerendy `jq` uruchomione na żywym runie (sprzątanie
  widzi dokładnie 4 zaległe ids; pętla czekania poprawnie kończy się błędem,
  gdy liczba ≠ 1).
