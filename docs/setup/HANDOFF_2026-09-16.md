## Werdykt audytu PR #123: APPROVE z zastrzeżeniami

Logika 27 commitów poprawna; deklaracja „E2 wyłącznie komentarze" potwierdzona
mechanicznie (V1: 0 niekomentarzowych linii); cytaty CR za każdą odznaką
zweryfikowane literalnie (mtg.wiki, CR effective 2026-08-07). Dwa błędy
naprawione w tej sesji, jeden dług dokumentacyjny domknięty:

- **A1 (M359, CR 514.3a) — naprawiona:** model cleanupu liczył tylko aktywność
  STOSU, a reguła dosłownie otwiera priorytet także po SAMYM wykonaniu SBA
  („…any state-based actions would be performed and/or any triggered
  abilities…"). Scenariusz potwierdzony sondu behawioralną: stwór utrzymywany
  EOT-buffem ginął w chwili wejścia w cleanup (514.2 zdejmuje buff → SBA
  704.5f), a okna nie było. Naprawa: `cleanupEventIsSbaEvidence` — dowody SBA
  w strumieniu zdarzeń (`creature_destroyed`, `object_moved` z polem `sba`,
  `permanent_sacrificed` Saga 704.5s, `token_ceased_to_exist`,
  `counter_removed`); w zamkniętym cleanupie te typy przychodzą wyłącznie
  z SBA (efekty żyją na stosu), więc brak drogi do fałszywego otwarcia.
  Świadomie poza zestawem: goły `object_moved` (discard 514.1 go emituje),
  `player_lost`, `legend_rule_choice_started`. Zero nowych pól stanu →
  fingerprint bez zmian. Testy T1–T3 (przed: 3× RED), mutacje: wyłączenie
  dowodu `creature_destroyed` → T1+T2 RED.
- **A2 (M360/B3, klasa L16) — naprawiona:** `pendingCombatSecondPass` (flaga
  drugiego kroku obrażeń przy first/double strike) blokuje rundę passów i
  zmienia przyszłe możliwości, ale nie trafiła do fingerprintu — dwa stany
  różniące się tylko tą flagą miały identyczny odcisk (replay i sonda no-op
  ślepe). Naprawa: pole w `PENDING_DECISION_FIELDS`. Przyczyna lukі:
  strażnik `fingerprint-pending-decisions.test.js` bierze ground truth z ciał
  `firstPendingDecision*`, a ta blokada siedzi w bramce pass-round — klasa
  blokad spoza firstPendingDecision nie ma automatycznego strażnika (patrz
  O2 w raporcie). Test T4 (przed: RED — identyczne JSON), mutacja: usunięcie
  wpisu → RED.
- **A3 (dokumentacja, L92) — domknięta:** README „Bieżący stan" i handoff 15c
  opisywały stan sprzed odznak (5555/5565 i 5514/5524 vs finalne liczby);
  README zaktualizowany pomiarami z finalnego HEAD, ten handoff zastępuje 15c.

## E3 = O5 (domknięcie z audytu #121): 24 sprostowania kontekstu 702.16

Pełny przegląd wszystkich wystąpień 702.16 w `src/` (60+) przeciw literalnemu
tekstowi (mtg.wiki/page/Protection, CR 2026-08-07: b=targetowanie, c=Aury,
d=Sprzęt/Fortyfikacje, e=prewencja, f=blokowanie atakujących) — systemowy
dryf podreguł w 8 plikach (G3 z #121 naprawił tylko 4 miejsca w bocie):
blokowanie cytowane jako a/e/d → f (combat ×4), prewencja jako a/d → e
(combat ×2, effects, permanents ×2), jakość jako d/e → a (effects,
permanents, attachments ×2, card-data, registry), equip jako c → d
(attachments), zakresy b–e → b–f (attachments ×2, render, bot — jakość
konsultują wszystkie bramy DEBT łącznie z blokowaniem), zła reguła cały:
`card-data.js` „This token can't block" cytował 702.16e → CR 509.1b (can't
block to NIE ochrona). Bonus: „Offspring, CR 702.16x?" ze znakiem zapytania
w kodzie → literalnie CR 702.175 (mtg.wiki/page/Offspring). Wszystkie
poprawki komentarzowe (diff -U0 bez linii nie-komentarzowych = pusty);
dotknięte pliki testowe 10/10 zielone.

## Pułapki / lekcje tej sesji

- **Odznaka regułowa nowego MODELU domyka pytanie: „jakie JESZCZE zdarzenia
  tej samej reguły CR otwierają ten sam efekt?"** — A1 to dokładnie pominięta
  gałąź „…and/or any state-based actions" z reguły, którą PR cytował
  poprawnie (cytat ✓, model niekompletny).
- **Nowa struktura blokująca priorytet = wpis do `PENDING_DECISION_FIELDS`
  NATYCHMIAST** — grep po `firstPendingDecision` nie wystarcza, gdy blokada
  siedzi w bramce passów (A2). Checklista L95 ma punkt „strażniki
  priorytetu"; rozszerzyć mentalnie o „blokady spoza firstPendingDecision".
- **`gh pr view <nr>` bez `--json` pada na GraphQL Projects (classic)** —
  zawsze `--json` (ENVIRONMENT §3). `git show <sha>` z PR-u wymaga fetcha
  gałęzi sesji (main ma tylko squash).
- **Sondy `.arena/`:** `applyEffect` przyjmuje targets jako **ID** (stringi),
  nie obiekty — bug pierwszych trzech sond; czwarta działa.
