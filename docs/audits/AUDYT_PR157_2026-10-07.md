## 1. Zgłoszenie D — engine (`triggers.js` +24, `effects.js` +4/−1)

**Zmiana:** skan triggerów po SBA nie widział aury, która odeszła do grobu
W TEJ SAMEJ komendzie co zaczarowany stwór (SBA zabiera hosta po śmiertelnych
obrażeniach, aurę po nim — bez legalnego gospodarza). Nowa pętla łączy zdarzenie
odejścia aury (`permanent_put_into_graveyard`, `reason: 'aura_without_legal_host'`,
`attachedTo` = id hosta) ze zdarzeniem obrażeń (`damage_dealt`, `ev.target` = id
hosta) i podnosi trigger aury z LKI aury + `enchantedHostLki: ev.targetLki`.
Po stronie efektu `damage_each_opponent` z `fromEnchanted` źródłem obrażeń jest
host: najpierw żyjący obiekt z `state.objects`, potem LKI hosta z kontekstu
triggera, na końcu aura.

**Weryfikacja:**
- **Kontrakt zdarzeń odejścia:** `attachedTo` na deparcie aury realnie niesie id
  hosta (attachments.js ~371) — ten sam kontrakt, którym żyje już Griffin Guide
  „when enchanted creature dies" (M271). ✔
- **Kolejność:** wymagane `indexOf(departure) > indexOf(damage)` — aura
  zniszczona/odebrana PRZED obrażeniami nie odpala; aura odeszła PO obrażeniach
  (SBA tej samej komendy) odpala. ✔
- **Brak podwójnego odpalenia:** gdy aura żyje, działa pętla wymagająca
  `zone === 'battlefield'`; pętla looks-back startuje tylko ze zdarzeniem
  odejścia. Wieloaury na jednym hoście: join po `attachedTo === ev.target` +
  filtr `trigger.event === 'enchanted_creature_dealt_damage'` — każda aura
  odpala niezależnie, ta sama aura nie odpala dwa razy. ✔
- **Tokenowy host:** token po śmierci jest kasowany (`state.objects.delete`,
  CR 704.5d); pętla looks-back bierze aurę z grobu po `toId`, a warunek wejścia
  (`victim.kind === 'creature'` + `ev.targetLki`) przechodzi na LKI ofiary —
  ścieżka nie łamie się na tokenie. ✔ (potwierdzone nowym testem D/4 w commit B)
- **LKI hosta w efekcie:** `state.objects.get(attachedTo)` zwróci martwego
  nie-tokena (zostaje w `state.objects` ze strefą `graveyard`), dla tokena
  zwraca `undefined` — wtedy jedyną szansą jest `context.enchantedHostLki`.
  **To właśnie ten fallback nie był przypięty testem (D-pin).** ✔ po fixie
- **„It deals" = stwór, nie aura:** `dmgSource` = host; „each opponent" liczone
  względem `sourceObject.controllerId` (kontroler aury = kontroler triggera,
  CR 603.3a) — poprawne. ✔
- **CR 608.2h (dosłownie):** „If an effect requires information from the game
  (such as the number of creatures on the battlefield), the answer is determined
  only once, when the effect is applied. If the effect requires information from
  a specific object, including the source of the ability itself, the effect uses
  the current information of that object if it's in the public zone it was
  expected to be in; if it's no longer in that zone... the effect uses the
  object's last known information. See rule 113.7a. If an ability states that an
  object does something, it's the object as it exists—or as it most recently
  existed—that does it, not the ability." — to JEST podstawa zarówno LKI hosta,
  jak i „to stwór zadaje obrażenia". Cytaty 608.2g/611.2c w komentarzach są
  więc błędne numerami (oba numery istnieją w tabeli, strażnik milczy).
- **CR 608.2g (dosłownie, dla kontrastu):** „If an effect gives a player the
  option to pay mana, they may activate mana abilities before taking that
  action. If an effect specifically instructs or allows a player to cast a spell
  during resolution... No other spells can normally be cast and no other
  abilities can normally be activated during resolution." — nic o LKI.
- **CR 611.2c (dosłownie):** „If a continuous effect generated by the resolution
  of a spell or ability modifies the characteristics or changes the controller of
  any objects, the set of objects it affects is determined when that continuous
  effect begins. After that point, the set won't change." — nic o źródle obrażeń.
- **CR 603.10 (dosłownie, zdanie pierwsze):** „Normally, objects that exist
  immediately after an event are checked to see if the event matched any trigger
  conditions... However, some triggered abilities are exceptions to this rule;
  the game 'looks back in time'..." Lista wyjątków: 603.10a (zone-change),
  603.10b (phasing out), 603.10c (becomes unattached), 603.10d (loses control),
  603.10e (spell countered), 603.10f (loses the game), 603.10g (planeswalks
  away). „Whenever enchanted creature is dealt damage" NIE jest na liście —
  trigger aury wypada po regule domyślnej, bo w chwili zdarzenia (obrażeń) aura
  wciąż wisia na hoście. Implementowana „rekonstrukcja stanu w chwili zdarzenia"
  jest więc zgodna z 603.10 (zdanie pierwsze) + 603.2g („An ability that
  triggers on damage being dealt won't trigger if all the damage is prevented"
  — trigger valutowany w chwili zdarzenia) + 608.2h (LKI przy resolution).
  Fraza „looks-back" w komentarzach jest luźna, ale spójna z konwencją repo dla
  tej samej klasy (M166/B, Enrage własnego stwora) — nie kwalifikuje jako błąd.
- **Dowód mutacyjny (L13), próba A:** neutralizacja nowej pętli
  (`departure.attachedTo === ev.target` zamiast `!==`) →
  `zgloszenie-d-pain-for-all-smierc-hosta.test.js` **RED** (D/1, D/3), D/2
  (host przeżył — inna ścieżka) GREEN. Testy D spinają realną zmianę. ✔
- **Dowód mutacyjny (L13), próba B:** usunięcie `?? context?.enchantedHostLki`
  w `effects.js` → **3/3 GREEN**. Fallback LKI NIE przypięty (D-pin). ✘→fix

## 2. Zgłoszenie D1 + D1-mirror — bot (`heuristic-bot.js` +50/−1, `heuristic-params.js` +14)

**Zmiana:** (a) atakujący dostał karę, gdy wśród kandydatów na blokerów jest
stwór z aurą odbijającą (deskryptor `enchanted_creature_dealt_damage` na aurze
z widoku, ADR 0002); koszt = wspólna drabina samouszkodzenia
(`selfLifeLossPenalty`, PMSSB-36) + odstraszacz po przekroczeniu progu udziału
w życiu (`reflectedDamageLifeRatio: 0.25`, `reflectedDamageDeterrent: 25`);
(b) blokujący dostał symetryczną karę, gdy ATAKUJĄCY ma aurę odbijającą —
`exchange.blockerDamage` (ile blokerzy realnie zadadzą) jest kwotą odbicia;
(c) `blockerDamage: effectivePower` w obiekcie wymiany, gdzie `effectivePower`
wyklucza blokerów zabitych w pierwszym kroku (first strike).

**Weryfikacja:**
- **Semantyka kwoty:** D1 — odbicie = moc zablokowanego atakującego
  (`blockedStats.power`) = tyle, ile zada zaczarowanemu blokerowi. D1-mirror —
  odbicie = obrażenia, jakie blokerzy zadażą atakującemu = tyle, ile host aury
  (atakujący) dostanie. Oba kierunki zgodne z „Whenever enchanted creature is
  dealt damage, it deals that much damage to each opponent". ✔
- **CR 702.7b (dosłownie):** „If at least one attacking or blocking creature
  has first strike or double strike as the combat damage step begins, the only
  creatures that assign combat damage in that step are those with first strike
  or double strike. After that step... the phase gets a second combat damage
  step. The only creatures that assign combat damage in that step are the
  remaining attackers and blockers that had neither first strike nor double
  strike as the first combat damage step began, as well as the remaining
  attackers and blockers that currently have double strike." — cytat w
  komentarzu `blockerDamage` jest TRAFNY (bloker zabity w pierwszym kroku nie
  bije w drugim). ✔
- **Bramki:** D1 wymaga `canBeBlocked && !diesBeforeDealingDamage(...)` — atak,
  który ginie zanim zada, nie odbija. D1-mirror wymaga `blockerObjs.length > 0`.
  ✔
- **Generyczność (ADR 0002):** rozpoznanie po deskryptorze triggera na aurze
  z widoku; zero gałęzi po nazwie/ID karty. Widok pola bitwy niesie
  `attachedTo`, `kind`, `controllerId` (game-state.js ~6920). ✔
- **Dowód mutacyjny (L13), próba C:** podmiana deskryptora w bramce D1 →
  `zgloszenie-d1-bot-atak-aura-odbijajaca.test.js` **RED** (D1/1, D1/4), D1/2
  (bez aury) i D1/3 (latający) GREEN. ✔
- **Dowód mutacyjny (L13), próba D:** podmiana deskryptora w bramce D1-mirror →
  `zgloszenie-d1-mirror-bot-blok-aura-odbijajaca.test.js` **RED** (D1M/1,
  D1M/4). ✔
- **Obserwacja D1-ctl:** obie kary nie sprawdzają, KTO kontroluje aurę. Gdy to
  BOT kontroluje aurę na cudzym stworze, odbicie trafia przeciwnika, a bot karze
  siebie (błąd heurystyki w naddzierańcu; wymaga efektów zmiany kontroli aury —
  poza katalogiem, ADR 0029). Bez zmiany w tej sesji: modyfikacja scoringu bota
  wymagałaby próbki benchmarku (ADR 0025) dla przypadku nierealnego w katalogu.

## 3. Audyt PR #156 domknięty w kodzie (`game-state.js` +30/−51, `resources.js` +7/−1, `session.js` +13/−2)

  w JEDNĄ eksportowaną funkcję `graveFreeCastEligibleXValues`. Semantyka
  zachowana (ta sama logika budżet + oferta, ten sam zestaw X); widok po
  refaktorze nie ma już własnej pętli. Deduplikacja przez `Set`. ✔
- **O2 (log etapowy):** `grave_free_cast_required` renderowany zależnie od
  `stage` (`x` / `card` / `target`) + gałąź domyślna. Kontrakt sprawdzony:
  emiterów jest trzy (`effects.js` stage `x`, `game-state.js` stage `card` i
  `target`) i każdy niesie pola opisane w szablonie (`xValue`, `cardId`). ✔
- **F2 (deathZoneFor przy auto-tapie Skarbu):** ręczne `toZone = 'graveyard'`
  zastąpione choke pointem `deathZoneFor(state, object)` — ta sama reguła co
  każda inna ścieżka poświęcenia (klasa L109/L41 zamknięta). ✔
- **Dowód mutacyjny (L13), próba E:** wyłączenie `landDropWastesLandfallPenalty`
  (`if (true) return 0`) → `audyt-pr156-landfall-kolejnosc.test.js` **RED**
  (F1/T1), testy negatywne GREEN. Pin PR #156 dodany w PR #157 działa. ✔
- **Próby F/F2/F3 (O1-pin):** F (wyłączenie `if (budget < mv) continue`),
  F2 (wymuszenie `hasOffer = true`) i F3 (wyłączenie `om <= budget` w pętli
  ofert) — każda na ORYGINALNYM pliku zostawia **4/4 GREEN**. Analiza: MV 3

  obserwowalna — to własność kodu, nie luka testu. ✘→fix (commit B): pin
