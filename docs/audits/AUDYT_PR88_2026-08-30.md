## Znaleziska

### A1 — symetryczna gałąź `cant_be_blocked` bez pina (L61)

r5b/D dodała wycenę okna ataku do DWÓCH gałęzi: `creatures_cant_block_this_turn`
(Ruthless Invasion — 7 testów D1/D2) i celowanego `cant_be_blocked`
(Enter the Enigma — „Symetrycznie…" zgodnie z komentarzem nagłówkowym pliku
testów, ale BEZ ani jednego testu). Mutacja M9 (`attackingWindow = true`,
`canAttack = true` — czyli cofnięcie całej logiki okna) przechodzi CAŁY
szybki rdzeń 3801/3801. Istniejący pin z 2026-08-16 („bot nadal celuje ewazją
we WŁASNEGO stwora") testuje tylko OKNO OTWARTE, więc niczego nie pilnuje.
Naprawa w tym PR: piny zamkniętego okna (main2, stwór tapnięty) + pin
otwartego okna w nowym scenariuszu.

### A2 — martwa opcja `showCycleHint` (L67/L5)

`renderHoverPreview(host, info, mode, { showCycleHint = true } = {})` dostała
opcję po to, by hover o STAŁYM torze (miniaturki w „Rozgrywce", r5/A) nie
pokazywał podpowiedzi „ · scroll zmienia tor" (ten hover nie ma metody
`cycle`). **Opcja nie jest nigdy przekazana `false`**: `showHoverPreviewAt`
wywołuje `renderHoverPreview` bez opcji, a `createScryfallHover` idzie przez
`showHoverPreviewAt`. Efekt: na karcie z lokalnym artId miniaturka
w „Rozgrywce" pokazuje podpowiedź, która kłamie (scroll nic nie zmienia).
Naprawa w tym PR: przekazanie opcji przez `showHoverPreviewAt` +
`showCycleHint: false` w `createScryfallHover` + pin.

### A3 — README „Bieżący stan" przestarzały (recydywa D1)

README mówi „3735/3735 testów (test:all), 56 modułów / 2894.7 kB" — to stan
po ETAPIE 1 PR #88 (commit `04c3c85`, naprawa D1 z audytu PR #87). Etapy 3–10
tego samego PR dodały 76 testów i 39 kB artefaktu; faktyczny stan:
**test:all 3811/3811, 56 mod / 2934.0 kB** (zmierzone w tej sesji).
Wniosek procesowy: aktualizacja README musi być ostatnim krokiem sesji
(za(commitem) etapów funkcjonalnych), nie środkiem — inaczej każdy kolejny
etap ją dezaktualizuje. Zapisane jako lekcja (L92) i naprawione w tym PR.
