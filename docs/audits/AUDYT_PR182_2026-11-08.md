## 4. Znaleziska

### F-1: `triggers.js` — 732.2c przy wejściu na pole (cytat nie tej reguły)

Wiersz ETB (przed naprawą):

```
// CR 732.2c / 702.145: daybound LUB nightbound przy designation=null
// ustawia dzień (setDayNight transformuje nightbound → daybound).
```

Dwa błędy w dwóch linijkach: (1) **732.2c nie rządzi wejściem** — to reguła
sprawdzenia w untapie („it remains neither”); wejście rządzą 702.145d
(daybound → dzień) i 702.145g (samotny nightbound → NOC). Kod poniżej
implementuje 702.145d/g POPRAWNIE (z dosłownym cytatem 702.145g) —
komentarz nagłówkowy opisuje inną regułę niż ta, którą kod wykonuje.
(2) Blankiet **„ustawia dzień”** przeczy gałęzi nocnej tego samego `if`-a.
Błąd starszy niż #182 (wcześniej stało tam 731.2c — też reguła untapu
w starym wydaniu), ale #182 go PRZECYTOWAŁO bez weryfikacji znaczenia,
a §3 raportu dorobiło fałszywą parafrazę (F-2c).

Naprawa (root cause, komentarz + pin): nagłówek ETB cytuje 702.145d/g
z opisem obu gałęzi, a 732.2c stanęło przy swoim prawdziwym domu —
wczesnym `return` w `applyDayNightAtTurnStart` („ani dzień, ani noc →
sprawdzenie się nie odbywa”). Strażnik dostał test 5: 732.2c występuje
w `applyDayNightAtTurnStart`, a blok ETB (`designation=null`) go nie
cytuje. RED→GREEN: pin RED na starym komentarzu, GREEN po naprawie.
