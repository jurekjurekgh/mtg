## Co obejmuje PR #84 (przegląd zmienionych obszarów)

### 1. Bot / heurystyka — `src/controllers/heuristic-bot.js`, `heuristic-params.js`
Zmiany wyceny (bez zmiany reguł silnika):
- **M239/1 (trample przez protekcję):** `attackerNeutralizedByProtection`
  — atak jałowy tylko gdy bloker z protekcją MOGĄ go zneutralizować; trampler,
  którego moc przekracza „lethal" (wytrzymałość, albo 1 przy deathtouch),
  zada nadmiar obrońcy (CR 702.19b/702.16c). Spójne z sonda silnikową
  (7/7 trample vs 1/1 pro-black → obrońca 20→14). ✓
- **M241 (Escape):** `escapeExileCostOf` + wycena w `resolve_escape_exile`
  i wariant `cast_escape`. Wycena kar za wygnanie liczona od N najtańszych
  kandydatów z `view.zones.graveyard` (bo podzbiory zniknęły z komendy),
  co zachowuje anti-over-fix (nie wypłaci 4 dobrych stworów za mill 4). ✓
- **M243 (activatableAbilities):** treść aktywowalnych zdolności czytana
  NAJPIERW z obiektu (`view.activatableAbilities`) — tokeny (Treasure) mają
  zdolność w deskryptorze obiektu, nie w card-data. Bez tego token dostawał
  `ability = undefined` i bot poświęcał Skarb na manę przy 3 nietapniętych
  lądach. ✓
- **M244 (equip):** wycena wartością dodaną nosicieli z otwartego stanu,
  kara gdy nic realnie nie dodaje. ✓
- **M245 (podzbiory minus-jeden):** w `boundedSubsets`/`legalBlockerOptions`
  dokładane warianty „wszyscy minus jeden" (cap 32, deterministyczne, te same
  reguły walidacji). ✓
- **M247 (czysty ląd):** `pureLandTarget` + `removalPureLandPenalty`; anti-overfix
  przez `removalAtLandByDesign` (spec `'land'` z deskryptora) — efekty
  projektowane pod niszczenie lądów (Vandalize) kary nie dostają. ✓
- **M248:** etykieta fizzle dla „destroy if least power". ✓
- **heuristic-params.js:** usunięte martwe `damageCreature*`/`damageLethalBonus`
  (po M237/4 `damageTargetValue` jest modelem per-cel); dodany
  `removalPureLandPenalty: 60`. ✓

### 2. Engine — `src/engine/game-state.js`, `spells.js`, `effects.js`, `triggers.js`, `combat.js`

  + handler `execute` + projekcja w `playerView` (`pendingEscapeExile` z
  kandydatami). W `playerView`: `entry.cantAttackStatic` (M243/F — statyczna
  niemowlność ataku) i `entry.activatableAbilities` (M243/E). Pola publiczne
  zgodne z ADR 0017 (informacja jawna). ✓
- **effects.js (M240/B):** `sourceCardId` w pending decyzji ETB-look — tytuł
  modala nazywa kartę-źródło. ✓

- **combat.js (M243/F, M245):** `staticAttackPrevented` wydzielone i współdzielone

  z wariantami „minus jeden". ✓

## Znaleziska

### E1 — `pendingEscapeExile` poza `PENDING_DECISION_FIELDS` (fingerprint) — **NAPRAWIONE**
- **Objaw (czytanie kodu):** M240/M241 wprowadziły dwukrokowy Escape; decyzja
  „wygnij N kart" (`state.pendingEscapeExile`) wstrzymuje priorytet, ale nie
  trafiła do `PENDING_DECISION_FIELDS` w `src/engine/fingerprint.js` (L16).
- **Dowód:** sonda `stateFingerprint` przed/po `cast_escape` z pendingem — odcisk
  był **identyczny** (test `pr84-fingerprint-escape-pending` RED przed fixem).
  Klasa L16/L18: sonda „oferta bez skutku" i weryfikacja replayu nie widziały
  zamrożonej decyzji Escape.
- **Naprawa (root cause):** dopisanie `'pendingEscapeExile'` do
  `PENDING_DECISION_FIELDS`. Test RED→GREEN
  (`test/pr84-fingerprint-escape-pending.test.js`) — czerwony przed, zielony po;
  mutacja (cofnięcie wpisu) ponownie czerwieni. `npm test` 3610→3611 zielone.

  celów stałych i wielocelów; `srcLegal` z LKI (źródło mogło umrzeć z SBA). ✓
- **M243/F statyczna niemowlność ataku:** wydzielenie bez zmiany zachowania
  `isLegalAttacker` (walidacja niezmieniona — L48). ✓
- **M245 podzbiory:** `[[], singles, allButOne, all].slice(0, cap)` — dla n=15
  dokładnie 32; deterministyczne (ADR 0005). ✓
