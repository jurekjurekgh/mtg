## 4. Znaleziska

### F-1 (KRYTYCZNY, reguły): Threshold Seton's Desire nie istnieje — `must_block_enchanted` zapisuje flagę, której nikt nie czyta, a warunek `minGraveyardCards` nie jest ewaluowany

- **Lokalizacja:** `src/engine/effects.js:7508-7517` (jedyna zmiana silnika dla Batch 73),
  `src/cards/card-data.js:5265-5275` (Seton's Desire), `src/engine/permanents.js` —
  `staticConditionHolds` (brak gałęzi `minGraveyardCards`).
- **Oracle (`docs/cards/scryfall-setons-desire.json`):** *„Enchant creature // Enchanted creature
  gets +2/+2. // Threshold — As long as there are seven or more cards in your graveyard, all
  creatures able to block enchanted creature do so."*
- **Podstawa regułowa (CR 2026-11-06, `.arena/cr-current.txt:2360`):** CR 509.1c — *„The defending
  player checks each creature they control to see whether it's affected by any requirements (effects
  that say a creature must block, or that it must block if some condition is met). If the number of
  requirements that are being obeyed is fewer than the maximum possible number of requirements that
  could be obeyed without disobeying any restrictions, the declaration of blockers is illegal."*
- **Mechanizm błędu:** efekt zapisuje `mustBlockEnchanted: true` **na aurze**, a cały łańcuch wymogów
  blokowania czyta wymóg **z obiektu blokera**: `blockingRequirementCount(object)`
  (`permanents.js:724`) = `object.blocksIfAble ? Math.max(1, object.blockRequirementCount ?? 1) : 0`,
  konsumowany przez `mandatoryBlockerIds` (`combat.js:370`), `fulfilledBlockRequirements`
  (`combat.js:2025`), `maximalRequiredBlocks` (`combat.js:2108`), `minimalMandatoryBlocks`
  (`combat.js:2148`), ziarna `blockerSeedAssignments` (`combat.js:1910`), walidację
  `blockerDeclarationViolation` (`combat.js:2001`), auto-deklarację w `pass_priority`
  (`game-state.js:6506-6515`) i `playerView` (`game-state.js:7586`). Flagi z aury nie czyta **nikt**
  (grep: 1 zapis, 0 odczytów). Niezależnie: warunek `{minGraveyardCards: 7}` nie ma gałęzi
  w `staticConditionHolds`, więc nawet zapis flagi nigdy nie następuje (pomiar: `null`).
- **Pomiar:** §2 (`probe-batch73.mjs`, `probe6-batch73.mjs` §1, `probe7-batch73.mjs` §a): grób p1 = 7
  kart → `staticConditionHolds` **false**; atak zaklętym 5/3, dwa stwory wroga (3/2 i 3/1) mogące
  blokować → **4 oferty `declare_blockers`, w tym pusta `{}`**, `execute({assignments:{}})` →
  **`ok=true`**, `state.combat.blockers = {}`.
- **Skutek produktowy:** karta w talii `dominaria-wrg` (pomiar: `1x Seton's Desire`) nie robi połowy
  tego, co wydrukowano; człowiek może legalnie nie blokować, a bot nie widzi wymogu. Wpis
  `supported` + `limitations: []` narusza ADR 0022.
- **Naprawa (E2):** (1) gałąź `minGraveyardCards` w `staticConditionHolds` (licznik = grób
  kontrolera aury, CR: „your graveyard"); (2) wymóg blokowania musi zasilać **ten sam** łańcuch co
  `blocksIfAble` — per-blocker wymóg celowany („musi blokować ATAKUJĄCEGO X"), liczony z aktywnej
  aury na atakującym, a nie z flagi na aurze; inaczej ziarna, auto-pass i walidacja rozjadą się
  (wniosek projektowy z §2: wszystkie sześć konsumentów czyta `blockingRequirementCount`).

### F-2 (KRYTYCZNY, reguły): „As long as this creature is equipped, it gets +1/+1" nie działa — warunek `equipped` nie istnieje w silniku

- **Lokalizacja:** `src/cards/card-data.js` (Leonin Lightbringer, `condition: { equipped: true }`

- **Oracle (`scryfall-leonin-lightbringer.json`):** *„Ward {2} (…) // As long as this creature is
  equipped, it gets +1/+1."*
- **Podstawa regułowa:** CR 301.5a (`.arena/cr-current.txt:1596`) — *„The creature an Equipment is
  attached to is called the ‘equipped creature.' The Equipment is attached to, or ‘equips,' that
  creature."*; warstwy: CR 613 (pump z umiejętności statycznej).
- **Mechanizm błędu:** `staticConditionHolds` obsługuje 13 kluczy (`enteredThisTurn`,
  `activePlayerIsController`, `gainedLifeThisTurn`, `minCardsDrawnThisTurn`, `minLandsControlled`,
  `controlsAnotherMulticolored`, `hasCounter`, `minCreatureCardsInGraveyard`, `controlsAnotherArtifact`,
  `controlsArtifact`, `minArtifactsControlled`, `enduringStory`, `minLevel`/`maxLevel`, `delirium`) —
  klucza `equipped` **nie ma**, więc nieznany warunek zwraca `false` (cichy no-op, klasa L21).
- **Pomiar:** §2 — P/T **3/2** przed i po `attachEquipmentToCreature('cloak-of-the-bat','leonin')`
  (`attachedTo = 'leonin'`), `staticConditionHolds(..., {equipped:true})` = **false**; Oracle: **4/3**.
- **Naprawa (E2):** gałąź `equipped` w `staticConditionHolds` — prawda, gdy do obiektu jest
  przyłączony Equipment (pole `attachedTo` załącznika + podtyp `Equipment`), jedno źródło z
  `attachmentRestrictions`/`attachments.js` (L41: oferta, walidacja i skutek z tego samego miejsca).

### F-3 (KRYTYCZNY, reguły): ETB Spring-Loaded Sawblades ignoruje kwalifikator celu — 5 obrażeń trafia we WŁASNEGO, NIETAPNIĘTEGO stwora

- **Lokalizacja:** `src/cards/card-data.js:5172`
  (`trigger: { event: 'enter_battlefield', requiresTarget: { type: 'creature', qualifier: { tapped: true, controller: 'opponent' } } }`),
  `src/engine/spells.js:1501` (`case 'creature'` w `legalTargetCandidates`) i `validateTargets`
  (ten sam plik) — żadne nie czyta `spec.qualifier`.
- **Oracle (`scryfall-spring-loaded-sawblades.json`, twarz przednia):** *„Flash // When this artifact
  enters, it deals 5 damage to target tapped creature an opponent controls. // Craft with artifact
  {3}{W} (…)"*
- **Podstawa regułowa:** CR 115.1 (`:841`) — *„Some spells and abilities require their controller to
  choose one or more targets for them. (…) These targets are declared as part of the process of
  putting the spell or ability on the stack."*; CR 601.2c (`:2472`) — wybór celu musi spełniać
  kryteria („as long as it fits the targeting criteria"); CR 608.2b (`:2799`) — *„If all its targets,
  for every instance of the word ‘target,' are now illegal, the spell or ability doesn't resolve."*
- **Mechanizm błędu:** `qualifier` jest w katalogu jedynym miejscem, gdzie ten kształt występuje
  (grep: 1 trafienie w `src/`), a `legalTargetCandidates` ma dla stanów/kontroli **osobne typy spec**
  (`tapped_creature` — `spells.js:1742`, `creature_opponent_controls` — `:1733`). Karta użyła
  deskryptora, którego silnik nie zna → zbiór kandydatów = **wszystkie stwory na polu bitwy**.
- **Pomiar:** §2 (`probe4` §C) — `damage_marked amount 5` na `ownUp` (własny, nietapnięty 3/1 —
  ginie), na `foeUp` (nietapnięty stwór wroga), na `foeTap` (poprawnie); przy pustym stole 0 obrażeń
  (fizzle poprawny). W żadnym scenariuszu nie pojawiła się oferta wyboru celu
  (`pendingTriggerTargets = []`), więc przy wielu legalnych kandydatach gracz też nie zdecyduje.
- **Naprawa (E2):** domknąć **klasę**, nie kartę: `qualifier` dla spec celu (`tapped`, `controller`)
  w jednym miejscu używanym przez enumerację (`legalTargetCandidates`), walidację (`validateTargets`)
  i oferty triggerów (`triggers.js`) — tak, żeby oferta, walidacja i skutek nie mogły się rozjechać
  (L41/L48); przy >1 legalnym kandydacie wystawić wybór celu (konwencja: wybór bez alternatywy nie
  jest decyzją — `test/lodestone-needle-craft-jeden-kandydat.test.js`).
