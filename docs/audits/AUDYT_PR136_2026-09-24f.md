### F-2 (średnie, regułowe — **dowód RED**) — kopia „enter as copy" w grobie nie jest celem „card from an opponent's graveyard"

Nowy wspólny predykat `zones.isCardInOpponentGraveyard` (`src/engine/zones.js:126`)
odsiewa tokeny heurystyką po polu `name`:

```js
return Boolean(object)
  && object.zone === 'graveyard'
  && object.name == null          // ← „obiekty kart mają name: null"
  && object.controllerId !== controllerId;
```

`name` noszą nie tylko tokeny: **kopia permanentu** powstała przez
`enterAsCopy` dostaje `name` = nazwę kopiowanego celu (`game-state.js:3899`,
CR 707.2) i **nie ma** `isToken` (`test/c-enter-as-copy-name.test.js:57`
przypina: „karta wchodząca jako kopia to NIE token"). Pole `name` nie jest
kasowane przy zmianie strefy (`objects.js:203` — spread `...object`), więc
poległa kopia leży w grobie z `name` ustawionym.

CR 108.2b wyklucza z bycia kartą **wyłącznie tokeny** („Tokens aren't
considered cards—even a card-sized game supplement that represents a token
isn't considered a card for rules purposes"). Karta wchodząca jako kopia to
w grobie zwykła karta swojego właściciela — jest legalnym celem.

**Dowód RED** (`/tmp/red-harpy-kopia.mjs`, Jwari Shapeshifter {1}{U}
„enter as a copy of any Ally" jako kopia Coralhelm Guide 2/1, właściciel p2;
śmierć od 5 obrażeń + SBA):

```
grób: { id: 'grave-0', cardId: 'jwari-shapeshifter', cardName: 'Coralhelm Guide',
        name: 'Coralhelm Guide', isToken: false, controllerId: 'p2', zone: 'graveyard' }
pula Harpy: [ 'goblin-piker' ]
isCardInOpponentGraveyard(grób, 'p1') → false   (oczekiwane: true)
```

Czyli Scavenging Harpy (THB, z batcha 59) **nie może** wygnać karty, którą
wolno jej wygnać, a Puppeteer Clique (`creature_card_in_opponent_graveyard`,
`triggers.js:412` — ta sama heurystyka `object.name == null`, sprzed PR #136)
nie może jej wziąć. Komentarz w `zones.js` wprost powołuje się na „wzorzec
Puppeteer Clique", więc PR #136 **przeniósł istniejącą wadę do nowego,
wspólnego źródła reguły** (3 miejsca wywołania: walidacja `spells.js:382`,
enumeracja `spells.js:1467`, enumeracja triggera `triggers.js:402`).

**Root cause i naprawa (Etap C):** czytać jawną flagę `!object.isToken`
zamiast heurystyki po `name` — w `zones.js` i w bliźniaczej gałęzi
`triggers.js` (L41: jedna reguła, L43: pole-jawna-flaga zamiast domysłu po
innym polu). Nowy pin w `test/`.

## 7. Werdykt

**APPROVE z zastrzeżeniami.**

PR #136 jest spójny: silnik dostaje reguły w warstwach najniższych (ADR 0002 —
w `src/engine` nie ma ani jednej nazwy karty z batcha 59), jedna reguła ma jedno
źródło (L41), nowe wyceny bota mają wymiar w `PlayerView` i pokrętła pod
nazwami, a testy przypinają zarówno zachowanie, jak i brak regresji (T0).
Warstwa adresowania CR z sesji 24b działa: 25 losowo wybranych numerów
zgadza się z bieżącym wydaniem co do treści.

Zastrzeżenia (naprawiane w Etapie C tego PR):

1. **F-2** — jedyna wada regułowa: heurystyka `name == null` zamiast jawnej
   flagi `isToken` odsiewa z celów „karta w grobie przeciwnika" poległe kopie
   „enter as copy" (dowód RED w §3). Zasięg wąski (Jwari Shapeshifter +
   przyszłe karty z `enterAsCopy`), ale to reguła, nie kosmetyka.
2. **F-1** — błędny adres reguły w nocie karty widocznej dla gracza
   (107.3a → 602.5d) + powtórka w handoffie.
3. **F-3** — komentarz M429 rozjeżdża się z pomiarem (Hill Giant 3/3, nie 4/4;
   +8, nie +6).

**Zalecenie procesowe (bez decyzji właściciela):** klasa F-1/F-2 (numer ↔
mechanika) jest dziś pilnowana wyłącznie w sekcji 702. Rozszerzenie tabeli
strażnika o pary spoza 702 (np. 602.5d ↔ „activate only as a sorcery",
611.2c ↔ „until end of turn", 514.2 ↔ cleanup) zamknęłoby tę lukę; to robota
na osobną sesję, bo wymaga zbudowania tabeli z dosłownego CR (ADR 0030).
