### F-2 (średnie, regułowe — **dowód RED**) — kopia „enter as copy" w grobie nie jest celem „card from an opponent's graveyard"

Nowy wspólny predykat `zones.isCardInOpponentGraveyard` (`src/engine/zones.js:126`)
odsiewa tokeny heurystyką po polu `name`:

```js
return Boolean(object)
  && object.zone === 'graveyard'
  && object.name == null          // ← „obiekty kart mają name: null"
  && object.controllerId !== controllerId;
```

`name` noszą nie tylko tokeny: **kopia permanentu** powstała przez
`enterAsCopy` dostaje `name` = nazwę kopiowanego celu (`game-state.js:3899`,
CR 707.2) i **nie ma** `isToken` (`test/c-enter-as-copy-name.test.js:57`
przypina: „karta wchodząca jako kopia to NIE token"). Pole `name` nie jest
kasowane przy zmianie strefy (`objects.js:203` — spread `...object`), więc
poległa kopia leży w grobie z `name` ustawionym.

CR 108.2b wyklucza z bycia kartą **wyłącznie tokeny** („Tokens aren't
considered cards—even a card-sized game supplement that represents a token
isn't considered a card for rules purposes"). Karta wchodząca jako kopia to
w grobie zwykła karta swojego właściciela — jest legalnym celem.

**Dowód RED** (`/tmp/red-harpy-kopia.mjs`, Jwari Shapeshifter {1}{U}
„enter as a copy of any Ally" jako kopia Coralhelm Guide 2/1, właściciel p2;
śmierć od 5 obrażeń + SBA):

```
grób: { id: 'grave-0', cardId: 'jwari-shapeshifter', cardName: 'Coralhelm Guide',
        name: 'Coralhelm Guide', isToken: false, controllerId: 'p2', zone: 'graveyard' }
pula Harpy: [ 'goblin-piker' ]
isCardInOpponentGraveyard(grób, 'p1') → false   (oczekiwane: true)
```

Czyli Scavenging Harpy (THB, z batcha 59) **nie może** wygnać karty, którą
wolno jej wygnać, a Puppeteer Clique (`creature_card_in_opponent_graveyard`,
`triggers.js:412` — ta sama heurystyka `object.name == null`, sprzed PR #136)
nie może jej wziąć. Komentarz w `zones.js` wprost powołuje się na „wzorzec
Puppeteer Clique", więc PR #136 **przeniósł istniejącą wadę do nowego,
wspólnego źródła reguły** (3 miejsca wywołania: walidacja `spells.js:382`,
enumeracja `spells.js:1467`, enumeracja triggera `triggers.js:402`).

**Root cause i naprawa (Etap C):** czytać jawną flagę `!object.isToken`
zamiast heurystyki po `name` — w `zones.js` i w bliźniaczej gałęzi
`triggers.js` (L41: jedna reguła, L43: pole-jawna-flaga zamiast domysłu po
innym polu). Nowy pin w `test/`.

### F-4 (średnie, UI/protokół — **dowód reprodukcji i RED**) — kreator celów liczy padding `null` zamiast realnych celów

`src/table/multi-target.js` buduje plan kreatora z **długości wektora**, a nie z
liczby celów w wektorze. Dla czarów z pozycją opcjonalną (wektor ma długość 4, w
tym `null`) daje to trzy sprzężone objawy:

- `minTargets`/`maxTargets` = 4/4 tam, gdzie karta mówi „up to three" (dla
  Memory's Journey: 3 realne + 1 pozycja zależna) — interfejs żąda pełnego
  wektora;
- worek kandydatów przyjmuje pozycję pustą (`filter((c) => c.length > 0)`
  dotyczy innego poziomu), więc obok poprawnych ofert leży kandydat
  `[null, null, null, null]`;
- `targetKey(targets)` (klucz akceptacji wariantu) zawiera `null`, więc dla
  kandydata z pustymi pozycjami nie zgadza się z żadnym wektorem zwracanym przez
  silnik — przycisk **„Zatwierdź" gaśnie** i karta jest nie do zagrania z planszy.

Dowód bez DOM-a (sondy `/tmp/sonda-multi-target.mjs`, `/tmp/sonda-kreator-mj.mjs`
na żywym silniku): `multiTargetPlanOf` dla Memory's Journey z trzema legalnymi
celami zwraca `minTargets=4 maxTargets=4` oraz kandydata o samych `null`;
`legalTargetCombos` w tym samym stanie oferowało poprawne wektory 3-elementowe —
czyli **silnik miał rację, kreator nie**.

**Naprawa:** `realSizes` = liczba nie-`null` w wektorze, liczona **wyłącznie** w
`multiTargetPlanOf` (patrz incydent w §9.4 — wyciek tego wzorca do innych planów
psuł `sacrificeCastPlanOf` i plan proliferate); klucz `targetKey` pomija `null`;
worek kandydatów nie przyjmuje pozycji pustej. Naprawa nie dotyka protokołu ani
`src/engine` (ADR 0002/0005) — to warstwa prezentacji.

### F-5 (niskie, regułowe — **dowód pomiarowy i RED**) — grupa jednego słowa „target" enumeruje permutacje zamiast zbiorów

`legalTargetCombos` (`src/engine/spells.js`) dla spellu z **jednym** deskryptorem
celu (grupa „do N") generował kolejno ważne wektory, czyli **permutacje tego
samego zbioru**. Pomiar na karcie z dwoma creature'ami: 6 ofert zamiast 5; dla
trzech: 17 zamiast 9.

Podstawa regułowa, dosłownie z bieżącego wydania (CR L151): „The same target
can't be chosen multiple times for any one instance of the word "target"", a
601.2c wymaga tylko wskazania, **co** jest celem dla danej instancji słowa —
kolejność dwóch różnych celów w jednej instancji „target" nie jest informacją.
Wystawianie graczowi sześciu ofert zamiast pięciu to nie tylko szum w UI:
pomniejsza realną przestrzeń wyborów i mnoży pracę walidacji.

**Naprawa:** w grupach o identycznych deskryptorach celu kanonizujemy kolejność
(identyfikatorzy posortowane) i usuwamy powtórki, czyli enumeracja przechodzi z
permutacji na kombinacje; grupy o różnych deskryptorach (np. „target creature" +
„target player") pozostają kartezjańskie, bo tam kolejność **ma** znaczenie.

**Skutki w pinach (nie są obejściem — to ten sam błąd w testach):** para
{m1, m2} w `test/real-cards-batch59.test.js` 2 → 1 oraz V/5b (Dead Ringers)
2 → 1 — oba piny liczyły permutacje jako osobne warianty. Nowe testy:
`test/audyt-pr136-kreator-up-to-three.test.js` (5 testów, obie naprawy, trzy
mutacje czerwienią).
