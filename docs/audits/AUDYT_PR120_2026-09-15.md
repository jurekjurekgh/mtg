## 3. `heuristic-bot.js` — szczegółowo

### 3.1 Okna Savage Surge (A) — POPRAWNE z obserwacjami

- `isSavageLikeSpell` — deskryptorowy (buff `buff_creature_until_end_of_turn`
  + `untap_permanent`, dokładnie 2 efekty) — ADR 0002 OK; katalog: jedyne
  2-efektowe instanty z tymi typami to Savage Surge i jego wzorce —
  specjalnego przypadku po nazwie NIE ma.
- `isSavageOffenseWindow` (własna tura, `beginning_of_combat`, stwór po
  odkręceniu atakować może — `!summoningSickness && power > 0`): poprawne
  okno (CR 509.2a — atakujący deklaruje się w kroku następnym; w tym kroku
  jest priorytet). Obserwacja O4: wewnętrzne `if (inCombat && …)` w gałęzi
  offense jest gałęzią niemal martwą (w `beginning_of_combat` `inCombat`
  jest false — nikt jeszcze nie atakuje).
- `isSavageDefenseWindow` (cudza tura, `declare_blockers`, cel nietapnięty,
  `!cantBlock`, przybliżenie flying/reach): poprawne przybliżenie (CR 509:
  blokowalność); skróty ewazji udokumentowane w kodzie.
- Gałąź wyceny: `trick + (target.power ?? 0)` — arbitralna premia mocy
  (O4, obserwacja).

### 3.2 Spare from Evil (B) — A4 (błąd wyceny) + O3

- Deskryptor karty: `protection: { notSubtype: 'Human', kind: 'creature' }`
  (card-data.js) — zgodny z Oracle „protection from non-Human creatures";
  gałąź wyceny rozróżnia ochronę po podtypie (`isSubtypeProtection`) od
  dotychczasowej generycznej (`combatOn ? 12 : -45`) — poprawne rozszerzenie,
  stare zachowanie zachowane dla innych kształtów.
- `protectionPreventsAnyLethal(view, notSubtype)` — symulacja „z/without
  ochrona" (obrażenia od źródeł-„non-Human" zerowane): semantyka DEBT
  („Damage by sources … (All such damage is prevented.)" — dodatek A).
  Dwie pętle (własny atakowany / własny bloker vs atakujący) — model
  spójny z `simulateCombat` (CR 510). **O3:** druga pętla zakłada ochronę
  WSZYSTKICH blokerów — poprawne dla Spare („Creatures you control gain
  protection…"), zawyżałoby dla hipotetycznej ochrony 1-celowej — dziś
  w katalogu tylko Spare niesie `kind: 'creature'`.
- **A4 (błąd):** `correctStep = ['declare_blockers', 'combat_damage', 'end_of_combat']`
  zawiera `end_of_combat`. Obrażenia bojowe są zadawane w kroku
  `combat_damage` (CR 510.2: „all combat damage that's been assigned is
  dealt simultaneously"; engine: `resolve_combat` w `combat_damage` →
  `jumpToStep('end_of_combat')`), więc ochrona nabyta w `end_of_combat`
  (CR 511.1: tam jest już priorytet) NIE PREWENUJE NICEGO z tej walki —
  `protectionPreventsAnyLethal` czyta blokerów z danych walki (obrażenia już
  w `object.damage`) i zwraca true dla walki, w której ochrona jest bezużyteczna
  → bot dostaje +35 za kartę, którą zużywa bez efektu. Okno powinno
  kończyć się na `combat_damage` (tam, przed `resolve_combat`, priorytet
  istnieje — engine udostępnia okno; po pasie aktywnego bloker może jeszcze
  rzucić i ochrona zadziała w 510.2).
- `// DEBUG` + skomentowany `console.log` wewnątrz funkcji (A5; klasa L58).

### 3.3 Drenaż biblioteki (E+F) — A1 (blokujący) + O1

- `LIBRARY_DRAIN_EFFECTS += draw_then_discard, mill_from_bottom` — poprawne
  (obie mechaniki istnieją; `drainAmount` liczy 1 dla `draw_then_discard`).
- `repeatLibraryDrain` (trigger ≠ one-shot × horyzont) teraz łapie Murder
  przy RZUCIE — kara za zagranie Murder z cienką biblioteką działa.
- `oneShotLibraryDrain` + `oneShotDeckOutPenalty` dla ETB/dies (Skaab
  mill 4): kara deck-outu przy rzucie działa (zapas < 0).
- **A1 (blokujący):** gałąź `resolve_optional_trigger_choice` w
  `libraryDrainTax` czyta:

  ```js
  const pending = view.pendingOptionalTrigger;
  const ability = pending?.ability;      // ← WIDOK NIE WYSTAWIA `ability`
  ```

  a `playerView` (game-state.js, sekcja `pendingOptionalTrigger`) wystawia
  tylko `{ sourceCardId, effect }` (kontrakt M221/B: `effect` = główny efekt
  decyzji, płytka kopia). `pending.ability` jest więc `undefined` w każdym
  przebiegu produkcyjnym → `drain` = 0 → kara NIGDY nie nalicza. Konsekwencja
  (repro): Murder of Crows, 4 karty w bibliotece, trigger `may draw` —
  wycena: `fire` = 50 (base `scoreCommand`) − 0 = **+50** vs `no fire` = 0 →
  bot odpala; przy kolejnej śmierci odpala znowu; … → deck-out przy 4
  kartach. **Zgłoszenie E właściciela nie zostało naprawione.** Root cause:
  naprawa pisała się do pełnego stanu (state.pendingOptionalTrigger.ability
  istnieje — triggers.js), a nie do kontraktu widoku (ADR 0017). Naprawa
  (E2 tej sesji): odczyt `pending.effect` (istniejące pole kontraktu) +
  test RED→GREEN.
- **O1:** gałąź `resolve_optional_draw` zwraca
  `oneShotDeckOutPenalty(view, 1)`, które jest 0 matematycznie zawsze
  (lib 0 → wczesny `return 0`; lib ≥ 1 → zapas ≥ 0 → 0). Martwa gałąź
  (L5); prawdziwa blokada deck-outu siedzi w `scoreCommand`
  (`resolve_optional_draw`: pusta biblioteka + `draw:true` → −100).
- Gałąź `resolve_optional_trigger_choice` ma guard `cmd.selfMill`
  (M167/B) — spójny z `scoreCommand` (wycena wyścigu 45/−35/−60) — OK.
- `libraryLossPenalty`: wczesny `return 0` dla `myLibraryCount === 0` —
  **O2**: komentarz uzasadnia go testami (K2/CR1); w realnej grze
  obronne (pusta biblioteka = nic do drenażu; deck-out przez DÓBRANIE
  rozstrzyga SBA), ale uzasadnienie produkcyjnego kodu odnosi się do
  kształtu testowego (zapach, nie błąd).

  pełne; dla nie-artefaktu pula = jednostki nieograniczone i źródła bez
  `spendOnly:'artifact'` — spójne z `resources.js` (CR 106.3). `_isArtifact`
  na descriptorze — wewnętrzne, OK.
- **A3:** `artifactPurposeFor(cmd, descriptor)` (main.js:1835) jest
  **zdefiniowany, ale niezwołany z nigdzie** — logika istnieje w DWA
  miejscu inline (IIFE w `manaWizardFor` + fallback w `refreshManaWizard`).
  Klasa L41/L5: trzy kopie jednej reguły, z czego jedna martwa. Komentarz
  twierdzi, że „funkcje wyciągane w teście vm mają własną kopię inline" —
  faktycznie `refreshManaWizard` JEST wyciągany w `test/m348-przerwanie-
  kreatora-many.test.js` (vm nie widzi scope bootstrapu, stąd konieczna
  autosuficjencja) — to uzasadnia KODIĘ w `refreshManaWizard`, ale nie
  martwą funkcję top-level. Naprawa (E3): realny przepływ (`manaWizardFor`)
  przez funkcję, kopia vm zostaje z uzasadnieniem.

## Dodatek A — źródła online (dostęp 2026-09-15, mtg.wiki, CR „The Hobbit" 2026-08-07)

- **CR 510.2** (Combat Damage Step): „Second, all combat damage that's been
  assigned is dealt simultaneously. … No player has the chance to cast spells
  or activate abilities between the time combat damage is assigned and the
  time it's dealt." (mtg.wiki/page/Combat_damage_step)
- **CR 510.3**: „Third, the active player gets priority." (jw.)
- **CR 511.1** (End of Combat Step): „The end of combat step has no turn-based
  actions. Once it begins, the active player gets priority." (mtg.wiki/page/
  End_of_combat_step) — konsekwencja: po 510.2 (obrażenia zadane) ochrona
  nabyta w 511 nie prewenuje niczego z tej walki (podstawa A4).
- **CR 511.3**: „As soon as the end of combat step ends, all creatures,
  battles, and planeswalkers are removed from combat." (jw.)
- **Protection (702.16, DEBT):** „Damaged by sources with the specified
  quality. (All such damage is prevented.)" (mtg.wiki/page/Protection) —
  prewencja dotyczy obrażeń, które BĘDĄ zadane; zadanych nie cofa (podstawa
  A4 i semantyki `protectionPreventsAnyLethal`).
- Numeracja: komentarze w kodzie engine cytują starszą numerację (508/510);
  po sweepie CR (L143) end-of-combat = 511. Semantyka bez zmian.
